# WorldSkills Module A 練習範圍與出題規則

## 1. 文件用途

這份文件供老師或選手自行設計 3 至 4 小時的 Module A 練習題。它把 WorldSkills Occupational Standards（WSOS）列出的能力轉成可出題的功能範圍，並以四份歷年 Module A 參考題標示哪些功能已經出現、哪些仍值得優先練習。

「所有可能會出的功能」無法等同於一張固定功能清單，因為同一能力可以換成無數主題及流程；比較可靠的方法，是完整覆蓋 WSOS 的能力家族，再從每個家族選出可驗收的應用功能。本文件就是這個功能地圖。

---

## 2. 四份參考題的共同出題規律

四份參考題的共同規律如下：

1. 題目以一個一般使用者能理解的應用情境包裝，不直接考框架語法。
2. 通常包含 3 至 6 個頁面或明確狀態，並以畫面流程串起多項能力。
3. 不只要求顯示資料，還會要求使用者操作、裝置能力、狀態保存、錯誤或取消流程。
4. 一題通常有一個主要高難度功能，再配合數個中小型功能；不會同時塞入多個需要大量基礎設施的能力。
5. 題目只說明可驗收結果，不指定演算法、資料結構、程式語言或框架。
6. 線框圖負責界定畫面可見內容；功能條文負責界定互動、狀態轉移及邊界情況。
7. 裝置功能不會孤立出現，通常與導覽、資料保存、分享、媒體或視覺回饋組合。
8. 評分可以從輸入、操作、畫面結果、重新啟動後狀態及系統介面完成情況直接觀察。

### 四份參考題已明顯出現的功能

- 倒數或計時；
- 旅遊日誌、地圖、地圖手勢、繪製及保存；
- 登入、收藏及清單狀態；
- 從相簿選圖、圖片縮放、移動及分享；
- 票券或圖片保存；
- 錄音及音訊播放；
- 影片播放、播放速度及留言；
- 陀螺儀控制、震動及音效；
- 2D 遊戲碰撞、障礙物、收集物及排名；
- 深層連結或桌面小工具；
- 螢幕錄製。

因此，若目標是擴大練習面，新的題目不應再把以上項目當成唯一核心。

## 3. 功能狀態標記

| 標記 | 意義 |
|---|---|
| **已出現** | 四份參考題至少有一份明確要求，仍可能再考，但不是新練習的優先選擇 |
| **部分出現** | 類似能力曾出現，但仍有重要變體未考 |
| **未見** | 四份參考題沒有明確要求，但 WSOS 有對應依據 |
| **條件式** | 在 WSOS 範圍內，但需要特定硬體、服務、資料或評分環境 |
| **不宜推定** | 大眾常見，但 WSOS 沒有直接列出；除非當屆技術說明另有允許，不宜作核心 |

## 5. 最值得優先練習、而四份題目未見的功能

以下能力兼具「WSOS 有直接依據」、「一般大眾應用常見」及「不需要過度特殊設備」，適合接下來優先出題：

1. **裝置狀態工具**：電量、充電、儲存、網絡、顯示資訊、不可用狀態。
2. **資料視覺化**：環形圖、長條圖、折線圖、兩組資料比較。
3. **系統檔案匯入／匯出**：選檔、取消、錯誤格式、建議檔名、完成結果。
4. **拍照完整流程**：權限、切換鏡頭、重拍、接受、方向及保存。
5. **加速度計互動**：搖晃確認、水平校準、動作觸發及避免重複觸發。
6. **應用中斷恢復**：背景化、自動草稿、重新啟動後繼續或放棄。
7. **復原／重做**：圖片標註、簡單畫布、清單編排或文字編輯。
8. **API 分頁與離線快取**：載入下一頁、重試、取消舊請求、離線資料。
9. **檔案或媒體上傳**：進度、取消、失敗重試及完成後狀態。
10. **關聯式本機資料**：把兩種實體連結起來，但用實際工作流程包裝，避免純 CRUD。
11. **無障礙與文字縮放**：閱讀順序、標籤、放大字體後的版面。
12. **多語言與格式切換**：固定字串、日期、數字及方向性一致更新。
13. **裝置與尺寸相容性**：小螢幕、大螢幕、不可用功能的合理降級。
14. **下載、離線閱讀與快取更新**：已下載標記、離線開啟、清除。
15. **故障排查與修正**：在部分完成的專案中修正可重現錯誤。

## 6. 有範圍依據但不宜隨便放進 3.5 小時題目的功能

這些功能不是不能考，而是必須由主辦方準備穩定條件：

| 功能 | 風險 | 出題前必須提供 |
|---|---|---|
| 藍牙掃描與連線 | 裝置、配對及權限差異大 | 指定周邊裝置、固定資料、斷線測試步驟 |
| Socket 即時通訊 | 伺服器狀態會影響評分 | 本地或穩定伺服器、訊息格式、重連情境 |
| 拍攝及壓縮大型影片 | 時間、容量及裝置效能差異 | 指定長度、大小門檻、測試裝置 |
| 3D 動畫 | 資源製作及效能成本高 | 模型、貼圖、動作及最低裝置規格 |
| 加密、解密及數位簽章 | 容易變成密碼學知識題 | 固定測試資料、金鑰、輸入輸出規格 |
| 背景定位或長時間感測 | 系統限制及耗電差異 | 權限流程、測試時間、平台可接受行為 |
| 效能門檻 | 結果依裝置而異 | 固定裝置、固定資料量、測量方法 |
| 外部第三方 API | 網絡、配額及憑證不穩定 | 離線替代端點、測試帳戶、錯誤回應 |

## 7. 大眾常見，但不應單憑「常見」推定一定在本範圍

以下功能可能在真實應用中很常見，但若 WSOS、Technical Description 或當屆 Competition Information 沒有明確涵蓋，不宜把它們當作 Module A 的核心評分能力：

- OCR 文字辨識；
- NFC 標籤讀寫；
- 生物識別登入；
- 擴增實境；
- 行事曆寫入；
- 聯絡人存取；
- 推播通知服務；
- 機器學習分類或生成式 AI；
- 付款及購買流程；
- 健康平台或穿戴裝置專屬資料。

可以把它們換成同一範圍內較穩定的能力。例如把 OCR 改成相機拍照加手動裁剪，把推播改成應用程式內狀態通知，把穿戴裝置改成加速度計或裝置效能參數。

## 8. 3.5 小時題目的組題公式

### 建議工作量

| 組成 | 建議時間 | 說明 |
|---|---:|---|
| 主要新能力 | 55–70 分鐘 | 本題唯一最高難度功能 |
| 完整狀態鏈 | 35–45 分鐘 | 載入、成功、錯誤、取消、恢復 |
| 系統或裝置整合 | 25–35 分鐘 | 權限、檔案、感測器或裝置參數 |
| 本機保存或資料顯示 | 25–40 分鐘 | 重新啟動後保留，或一個圖表 |
| 頁面、導覽及基本介面 | 30–40 分鐘 | 3 至 5 個頁面或主要狀態 |
| 整合、修正及自測緩衝 | 25–35 分鐘 | 不應把 210 分鐘全部塞滿 |

### 建議限制

- 3 至 5 個主要頁面；對話框可另計。
- 只選 1 個最高難度核心能力。
- 裝置權限最多 2 種。
- 最多 1 個外部服務；必須有穩定的測試替代方案。
- 最多 1 個主要圖表頁；避免把題目變成統計作業。
- 至少 1 個取消流程、1 個錯誤流程及 1 個重新啟動後狀態。
- 資源檔只提供完成功能所必需的內容，不用大量資料掩蓋真正能力。
- 不把 JSON 解析、列表 CRUD、純 UI 臨摹或倒數計時作為整題核心。

### 組合句型

用以下公式可以快速產生題目：

> 一個日常情境  
> ＋ 一個未見的主要能力  
> ＋ 一個裝置／系統整合  
> ＋ 一個狀態保存或視覺回饋  
> ＋ 成功、取消、失敗及恢復  
> ＝ 一份 Module A 練習題

例：

> 搬家前檢查裝置  
> ＋ 取得裝置參數  
> ＋ 系統檔案匯出  
> ＋ 保存及比較兩份快照  
> ＋ Unavailable、取消匯出、重新啟動保留  
> ＝ "Device Snapshot"

## 9. 可直接使用的原創題目種子

以下種子只列出方向，正式出題時仍要補齊頁面、狀態、驗收及線框圖。

### 種子 1："Level Check"

- 核心：加速度計判斷物件是否保持水平。
- 配套：校準、震動回饋、保存三次量測結果。
- 邊界：感測器不可用、校準取消、旋轉裝置。

### 種子 2："Pack Proof"

- 核心：拍照、重拍、接受及在圖片上拖放編號標記。
- 配套：復原／重做、系統檔案匯出。
- 邊界：相機拒絕、拍攝取消、標記超出圖片範圍。

### 種子 3："Offline Brief"

- 核心：下載指定文章供離線閱讀。
- 配套：快取狀態、清除下載、離線開啟。
- 邊界：下載失敗、取消、內容更新。

### 種子 4："Receipt Bundle"

- 核心：從系統檔案選擇器匯入多個檔案並建立一個本機資料包。
- 配套：檔案格式驗證、移除、重新命名、匯出摘要。
- 邊界：取消選擇、不支援格式、重複檔案。

### 種子 5："Queue Pulse"

- 核心：以長條圖顯示固定 API 的即時等候狀態。
- 配套：手動重新整理、最後更新時間、離線快取。
- 邊界：伺服器錯誤、重試、舊請求較晚返回。

### 種子 6："Draft Rescue"

- 核心：多步驟表單的自動草稿及中斷恢復。
- 配套：附件選擇、進度、放棄草稿。
- 邊界：切到背景、強制關閉、重新啟動。

### 種子 7："Storage Lens"

- 核心：以環形圖與長條圖呈現裝置儲存狀態。
- 配套：建立快照、比較、文字報告匯出。
- 邊界：數值不可用、匯出取消、零容量保護。

### 種子 8："Quiet Transfer"

- 核心：上傳一個使用者選擇的檔案。
- 配套：進度、暫停／取消、完成紀錄。
- 邊界：網絡中斷、重試、重複提交。

### 種子 9："Accessible Cards"

- 核心：在標準字體及最大文字縮放下完成相同操作。
- 配套：閱讀順序、標籤、鍵盤或輔助操作。
- 邊界：小螢幕、長文字、錯誤訊息。

### 種子 10："Pair Check"

- 核心：掃描並連接指定藍牙測試裝置。
- 配套：顯示信號、接收固定值、保存紀錄。
- 邊界：拒絕權限、找不到裝置、斷線及重連。

## 11. 出題時不可寫的內容

不要向選手提供以下實作提示：

- 使用哪一種陣列、樹、佇列或資料庫表設計；
- 使用哪一個排序、碰撞、平滑或比較演算法；
- 使用哪個第三方函式庫；
- 使用哪個平台專屬類別、元件或 API 名稱；
- 應在哪一個生命週期方法保存狀態；
- 可直接複製的主要功能程式碼。

把提示改寫成可驗收結果：

| 不合適寫法 | 技術中立寫法 |
|---|---|
| 使用某排序函式依日期降序 | 項目必須由新至舊顯示 |
| 使用某本機資料庫保存 | 重新啟動應用程式後資料仍然存在 |
| 使用某平台檔案 API | 開啟系統提供的檔案儲存介面 |
| 使用某圖表套件畫環形圖 | 環形圖填滿比例必須與數值一致 |
| 用特定感測器監聽方法 | 裝置傾斜時畫面物件作出指定反應 |

## 12. 線框圖製作規則

1. 先寫介面要求並給每項唯一編號，再畫線框圖。
2. 一個介面要求可以包含一個完整區塊，但不能把無關控制項藏在同一編號。
3. 線框圖必須出現每一個可見標題、欄位、按鈕、狀態及必要資料。
4. 線框圖不得增加介面要求沒有提到的搜尋、設定、更多選單、浮動按鈕或圖示。
5. 動態狀態需要獨立線框圖，例如空白、有資料、錯誤、選中或對話框。
6. 如果一個元素只在特定狀態出現，要在圖下清楚註明條件。
7. 線框圖中的示例數值不得與功能要求衝突。
8. 完成後建立逐項對照表，不能只靠肉眼大概檢查。

## 14. 快速審核分數

正式使用前，每題以 0、1、2 分自評：

| 項目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 範圍依據 | 無明確依據 | 間接相關 | WSOS 直接列出 |
| 新穎度 | 重複歷題核心 | 舊能力新組合 | 四份題目未見的核心 |
| 可驗收性 | 主觀或模糊 | 部分可觀察 | 輸入、操作、結果明確 |
| 工作量 | 明顯過少／過多 | 接近但不穩 | 3.5 小時且有緩衝 |
| 技術中立 | 指定實作方式 | 少量平台暗示 | 只描述結果 |
| 狀態完整 | 只有成功路徑 | 有一種邊界 | 成功、取消、失敗、恢復 |
| 線框一致 | 多項缺漏 | 少量不一致 | 全部逐項對應 |
| 環境穩定 | 依賴不可控服務 | 有部分替代 | 可離線或完全可控 |

**建議門檻：** 16 分滿分中至少 13 分，且「範圍依據」、「可驗收性」、「工作量」及「線框一致」不得為 0 分。

## 15. 本工具包的新題如何符合

同資料夾的 "Device Snapshot" 題目選用四份參考題未見、但 WSOS 直接涵蓋的「行動終端效能參數」與「視覺化資料」：

- 核心不是倒數、JSON、登入或媒體播放；
- 有真實裝置資料及不可用狀態；
- 有保存、重新啟動後保留、刪除及比較；
- 有環形圖與比例條，但沒有把題目變成統計分析；
- 有系統檔案匯出及取消流程；
- 每個頁面均分開列出介面與功能要求；
- 每項介面要求均在線框圖與對照表中出現。
