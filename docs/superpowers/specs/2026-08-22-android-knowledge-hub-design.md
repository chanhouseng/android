# Android Notebook 網站重整設計規格

日期：2026-08-22
狀態：待使用者審閱
範圍：第一階段——閱讀、搜尋與分類

## 1. 目標與限制

這個網站是單一使用者的 Android 個人知識庫，主要工作是在手機或電腦上快速找回曾經記錄的知識與專案做法。

第一階段提供：

- 不需登入即可閱讀。
- 合併 `knowledge/index.html` 與 `forgot.html` 的知識內容，不保留來源差異。
- 以 Android 組件為主軸分類知識，並可搜尋組件、功能、說明和程式碼。
- 將專案清楚分為「知識點項目」與「題目項目」。
- 以狀態和技術標籤篩選專案。
- 在手機和電腦提供一致且容易操作的介面。

第一階段不提供：

- 登入、權限或多人使用。
- 後端資料庫與跨裝置內容編輯。
- 網站內直接新增或修改內容。
- 重寫所有舊專案詳情頁。

日後加入編輯器時，閱讀頁不需登入；只有編輯模式需要驗證和同步儲存。本階段只預留資料結構，不實作這些功能。

## 2. 技術方向

新版採用 React、TypeScript 和 Vite，輸出可部署的靜態網站。路由採用 hash-based routing，避免靜態主機沒有 rewrite 規則時直接開啟子頁失敗。

應用分為四個清楚邊界：

1. `data`：知識與專案的結構化內容，只存資料，不包含畫面邏輯。
2. `search`：文字正規化、索引、排序與篩選，不依賴 React。
3. `features`：首頁、知識庫、專案等功能模組。
4. `shared`：導覽、搜尋框、標籤、程式碼區塊、空狀態和錯誤狀態等共用元件。

這些邊界讓日後把靜態資料替換成後端 API 時，不必改寫搜尋和大部分畫面。

## 3. 導覽與頁面

### 3.1 全站導覽

電腦版使用固定在應用左側的導覽列；手機版改為三個主要入口的緊湊導覽。兩者包含：

- 首頁
- 知識庫
- 專案

舊的 `page1.html`、`page2.html` 和其他根目錄舊頁保留原檔，但不出現在新版導覽。

### 3.2 首頁

首頁的首要操作是搜尋，不使用統計卡片或無關資訊分散注意力。

首頁包含：

- 一個跨知識與專案的主要搜尋框。
- 清楚說明可搜尋組件或功能，例如 `Progress`、`TabLayout`、`AlertDialog 背景透明`。
- 「知識庫」與「專案」兩個入口。
- 少量常用組件捷徑；捷徑來自資料，不在元件中寫死。

### 3.3 知識庫

知識庫先按 Android 組件收納，再列出該組件的具體功能。例子：

- `AlertDialog`
  - 背景設為透明
  - 變成全螢幕
- `Progress`
  - 設定進度顏色
- `Intent`
  - 開啟地圖
  - 開啟瀏覽器
  - 撥打電話
  - 開啟郵件

每個知識點可以有一個主要組件和多個別名或輔助標籤。主要組件決定它在組件索引中的位置；輔助標籤用於搜尋，不建立重複內容。

知識點可展開閱讀完整說明和程式碼。行動版保持單欄，程式碼區塊可水平捲動，不壓縮字體。

### 3.4 專案

專案提供兩個明確類型：

- `world skill`：知識點項目，集中練習單一或多個知識點。
- `homework`：題目項目，依完整題目製作，知識較多且結構較複雜。

兩種類型在同一個專案頁顯示，但可用類型篩選。每張專案卡顯示：

- 專案名稱
- 專案類型
- 原有摘要
- 狀態標籤
- 技術標籤
- 預覽圖片（存在時）
- 詳情筆記連結
- 原題目或訓練素材連結（存在且有效時）

第一階段保留現有專案詳情 HTML 作為內容來源。新版負責專案索引、搜尋與篩選；點擊專案後開啟原有詳情頁，不把所有大型詳情頁一次重寫成 React。

`world skill/index.html` 與 `homework/index.html` 保留為相容入口，並導向新版專案頁的相應類型篩選。

## 4. 資料模型

### 4.1 知識資料

每個知識點包含：

```ts
type KnowledgeItem = {
  id: string
  component: string
  title: string
  category: string
  aliases: string[]
  keywords: string[]
  description?: string
  codeBlocks: Array<{
    language: "kotlin" | "xml" | "text"
    code: string
    note?: string
  }>
  media: Array<{
    type: "image"
    src: string
    alt: string
  }>
  relatedLinks: Array<{
    label: string
    href: string
  }>
}
```

規則：

- `component` 是主要組件分類，例如 `AlertDialog`、`Progress`、`TabLayout`。
- `category` 是較廣的輔助分類，例如「介面與元件」、「資料與儲存」、「網絡與 API」、「圖片／媒體／檔案」、「動畫與互動」、「日期與時間」、「其他」。
- 原有廣東話筆記、說明和程式碼原樣保留；只統一新版介面文字為繁體中文。
- 原有知識圖片完整保留；缺少替代文字時，以知識點標題產生清楚的圖片說明。
- 無法確定組件的內容歸入「待分類」，不自行猜測。
- 空白範本項目不匯入正式資料。

### 4.2 專案資料

```ts
type ProjectItem = {
  id: string
  title: string
  type: "knowledge-project" | "assignment-project"
  status: "complete" | "in-progress" | "rebuild" | "broken" | "unmarked"
  summary: string
  tags: string[]
  image?: string
  detailHref?: string
  sourceHref?: string
}
```

狀態處理規則：

- 明確寫有「未做晒」的項目標為「進行中」。
- 明確寫有「爛尾」或「要重新做」的項目標為「待重做」。
- 明確寫有「壞咗」的項目標為「損壞」。
- 只有原內容明確表示完成時才標為「完成」。
- 沒有足夠資訊時標為「未標記」，不假設已完成。
- 原有說明文字仍完整保留，不以狀態標籤取代。

## 5. 搜尋與篩選

搜尋不分英文大小寫，忽略字串首尾空白，支援中文子字串和英文部分字串。

### 5.1 搜尋範圍

知識搜尋比對：

- 組件名稱
- 功能標題
- 組件別名
- 輔助分類與關鍵字
- 說明文字
- 程式碼

專案搜尋比對：

- 專案名稱
- 類型
- 狀態
- 摘要
- 技術標籤

首頁搜尋同時搜尋兩種資料，結果按「知識」與「專案」分組顯示。

### 5.2 排序

搜尋結果依下列優先次序排序：

1. 組件或專案名稱完全符合。
2. 功能標題或專案名稱以關鍵字開頭。
3. 組件別名或技術標籤符合。
4. 說明或程式碼包含關鍵字。

同一優先級保持資料原有順序，避免結果每次跳動。

### 5.3 篩選

知識庫可按主要組件和廣泛分類篩選。專案可同時按類型、狀態和技術標籤篩選。搜尋字串與篩選條件可以一起使用。

當搜尋沒有結果時，畫面會顯示目前的搜尋字串、已啟用的篩選，並提供「清除篩選」操作。

## 6. 視覺設計

設計名稱為「Android Notebook」，靈感來自 Android Studio 的專案樹與 Kotlin 語法色，而不是一般管理儀表板。

### 6.1 色彩

- 深墨藍：主要導覽與高對比結構。
- Android 綠：知識、組件和主要互動狀態。
- Kotlin 紫：程式碼、專案類型和技術內容。
- 淺灰藍：頁面背景與分隔。
- 琥珀／紅色：進行中、待重做或損壞狀態。

色彩不是唯一狀態訊號；所有狀態同時顯示文字。

### 6.2 字體與結構

- 介面與繁體中文使用清晰的無襯線字體。
- 組件名稱、路徑、鍵盤提示和程式碼使用等寬字體。
- 首頁只在搜尋區建立明顯視覺焦點。
- 組件索引使用類似專案樹的結構，表達真實的內容階層。
- 動效只用於頁面切換和展開內容，並遵守 reduced-motion 設定。

### 6.3 響應式與無障礙

- 支援至少 320px 寬的手機畫面。
- 所有互動元件可以用鍵盤操作，並有可見焦點。
- 使用語意化標題、導覽和按鈕。
- 搜尋結果數量與空狀態使用適當的 live region。
- 程式碼不因窄螢幕縮小至難以閱讀。
- 文字與背景達到清楚可讀的對比。

## 7. 內容遷移

### 7.1 知識

遷移工具讀取 `knowledge/index.html` 和 `forgot.html` 中既有的 accordion 標題與內容，產生初步結構化資料。遷移後需逐項檢查：

- 標題與程式碼沒有遺漏。
- 圖片路徑和圖片說明可以正常顯示。
- 內部連結仍指向正確檔案。
- `forgot.html` 內容不附加「易忘」或來源標記。
- 不能確定的組件放入「待分類」，列入人工確認清單。

兩個舊檔在完成核對前不刪除。

### 7.2 專案

遷移工具讀取 `world skill/index.html` 與 `homework/index.html` 的卡片資料，建立專案索引。處理原有空白卡片、錯誤副檔名和不存在的連結時，不補猜內容：

- 空白卡片不顯示。
- 缺少詳情頁的專案仍可顯示，但標示「詳情未提供」。
- 無效題目連結不提供可點擊操作，並列入遷移報告。
- 無法確定的狀態使用「未標記」。

原有詳情頁、圖片與訓練素材不移動，以免破壞既有相對路徑。

## 8. 錯誤與退化處理

- 資料欄位缺失：開發與建置時報出具體項目 ID 和欄位；正式畫面使用安全的替代文字。
- 圖片遺失：顯示中性的無圖片狀態，不顯示破圖圖示。
- 詳情或題目連結無效：禁用該操作並顯示「連結未提供」。
- 搜尋無結果：保留搜尋字串，顯示清除搜尋或篩選的方式。
- JavaScript 載入失敗：基本頁面仍顯示網站名稱和重新載入提示。

## 9. 測試策略

### 9.1 單元測試

- 搜尋文字正規化。
- 英文大小寫、中文子字串和英文部分字串搜尋。
- 搜尋排序優先級。
- 多個專案篩選條件組合。
- 狀態映射與「未標記」退化規則。
- 無效或缺少資料的驗證。

### 9.2 元件與整合測試

- 首頁搜尋能導向分組結果。
- 組件篩選只顯示相應知識。
- 專案類型、狀態和標籤可組合。
- 清除篩選能恢復完整結果。
- Accordion、導覽和篩選可以用鍵盤操作。
- hash route 重新載入後仍能開啟正確頁面。

### 9.3 端對端與內容驗證

- 在桌面與 390px 手機寬度完成主要閱讀流程。
- 搜尋 `progress`、`TabLayout` 和「AlertDialog 背景透明」均得到相應資料。
- 檢查所有專案圖片、詳情頁與題目連結。
- 比對遷移前後的知識項目數量及標題，確認沒有靜默遺漏。
- 執行正式建置並從產物啟動靜態預覽。

## 10. 完成條件

第一階段在以下條件全部達成時完成：

- 新版首頁、知識庫和專案頁可在手機與電腦使用。
- `knowledge/index.html` 與 `forgot.html` 的有效內容已完整合併。
- 知識可按組件瀏覽，指定的三個搜尋例子均可找到正確內容。
- `world skill` 與 `homework` 專案可清楚分開和篩選。
- 明確的專案狀態已轉成標籤；不確定項目沒有被擅自判定。
- 舊頁和專案資產沒有被刪除或移動。
- 自動化測試、連結檢查和正式建置通過。
