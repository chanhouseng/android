# WorldSkills Android Kotlin 備賽平台設計規格

日期：2026-08-03

狀態：待使用者審閱

目標比賽日期：2026-09-22

## 1. 專案定位

本專案把現有 Android Kotlin 靜態網站升級為單一使用者的 WorldSkills 備賽平台。平台的首要目標不是公開教學或作品展示，而是讓使用者在比賽前快速找回忘記的 API 與關鍵字、從歷史項目取得解題思路，並在手機零碎時間接受 AI 出題及程式碼評估。

平台只服務一位管理者。所有頁面登入後才能使用，不提供公開瀏覽、註冊、社群、多人權限或正式 Android 雲端編譯。

## 2. 成功條件

平台完成後必須支援以下四條核心路徑：

1. 輸入中文、英文、Android API 或程式碼關鍵字，找到知識點、程式碼、項目及 PDF 內容。
2. 從歷史項目查看簡介、示範影片、使用流程、功能拆解、關聯知識點及完整程式碼。
3. 在手機或電腦接受功能邏輯題或關鍵字記憶題，輸入 Kotlin／XML 程式碼並取得 DeepSeek 評估。
4. 將不會、答錯或網站未收錄的內容自動保存到「待學習」，其後整理成正式知識點。

AI 評估以「在 2.5 小時比賽內最快正確完成」為首要標準，不因缺少正式專案架構而否定可行的比賽快速寫法。

## 5. 核心操作流程

### 5.1 搜尋答案

```text
首頁或搜尋頁輸入內容
→ 即時搜尋現有資料
→ 按全部／知識點／程式碼／項目／PDF 篩選
→ 開啟結果詳情或直接複製程式碼
→ 查看相關知識點、項目與 PDF
```

使用者可輸入 API 名稱、中文功能描述、邏輯需求、項目名稱或程式碼片段。搜尋結果按以下優先級排序：

1. 標題完全符合
2. API、標籤或搜尋別名符合
3. 程式碼內容符合
4. 項目簡介或使用流程符合
5. PDF 文字符合

每個結果顯示標題、內容類型、命中片段、來源、標籤及可用操作。

找不到結果時，不自動消耗 AI 額度。頁面提供「詢問 DeepSeek」按鈕；AI 回答可由使用者一鍵保存到待學習。

### 5.2 查看歷史項目

```text
項目列表
→ 按功能、年份、Module、手機／平板篩選
→ 項目詳情
→ 使用流程、功能拆解、知識點或完整程式碼
→ 跳到相關項目、PDF 或練習題
```

項目詳情固定採用以下內容順序：

1. 項目名稱與簡介
2. 可選的操作示範影片
3. 圖文使用流程
4. 功能拆解
5. 關鍵知識點
6. 完整程式碼檔案樹與檢視器
7. 從項目提取的比賽快速片段
8. 相關項目、PDF 及 AI 題目

沒有影片的項目不顯示空白影片區塊。影片支援上傳檔案或填寫網址，並可設定封面及說明。

完整程式碼按實際檔案樹呈現。檢視器支援語法高亮、行號、複製、檔案內搜尋及全螢幕閱讀。點擊「練習此檔案」後建立暫存副本；編輯不會直接覆蓋正式程式碼。

### 5.3 AI 抽題與作答

抽題入口只保留三種模式：

- 隨機混合
- 功能邏輯題
- 關鍵字記憶題

功能邏輯題可涵蓋 JSON／CSV／XML 資料處理、REST API、篩選與分析、動態 UI、座位生成、表單驗證、檔案處理、加密及其他 WorldSkills Module A 類型要求。

關鍵字記憶題可詢問相機、檔案選擇、Intent、權限、Activity Result API、系統功能 API 等需要記住的設定與程式碼。

```text
選擇題型
→ DeepSeek 產生題目、資料及明確要求
→ 使用者在 Kotlin／XML 編輯器回答或點擊「我不會」
→ DeepSeek 逐項評估
→ 顯示最小修改、比賽最快寫法及完整參考答案
→ 保存答題紀錄
→ 必要時建立待學習內容
```

評估結果包含：

- 已完成要求
- 遺漏要求或錯誤
- 最小修改建議
- 比賽最快寫法
- 完整參考答案
- 相關知識點、項目與 PDF

本期不執行或編譯提交的程式碼。所有結果必須標示為「AI 分析結果」，不能宣稱答案已通過真實編譯或自動測試。

### 5.4 待學習

以下情況自動建立待學習內容：

- 使用者點擊「我不會」
- AI 判定答案存在重要錯誤
- AI 題目包含網站尚未收錄的新知識
- 搜尋無結果後取得 DeepSeek 補充答案

每條內容保存原始問題、題型、使用者答案、AI 評語、比賽最快寫法、完整參考答案、建立日期及關聯內容。

可用操作為：再次作答、編輯內容、轉為正式知識點及刪除。系統使用標題、API 關鍵字與內容相似度偵測重複項目；相似內容預設提示合併，不靜默刪除或覆寫。轉為正式知識點後從待學習列表移除，但答題紀錄保留。

### 5.5 內容管理與匯入

現有內容匯入流程：

```text
選擇 HTML、項目資料夾或 PDF
→ 解析標題、文字、程式碼、圖片及檔案關係
→ 顯示匯入預覽
→ 使用者確認名稱、類型與關聯
→ 寫入正式資料
```

無法可靠分類的內容進入「需要整理」，不直接發布。匯入不刪除、不移動及不覆寫原始檔案。

網站內新增流程：

```text
選擇知識點／項目／PDF
→ 填寫內容並上傳附件
→ 儲存草稿
→ 預覽
→ 發布
```

正式內容可從網站後台修改。所有內容另可匯出為結構化備份，程式碼及附件可一併下載或保存到 GitHub。

## 7. 技術架構

採用可部署到華為雲或阿里雲的容器化單體架構，避免第一版過早拆成多個服務。

### 7.1 建議技術組合

- 前端與伺服器：Next.js + TypeScript
- 資料庫：PostgreSQL
- ORM 與資料遷移：Prisma
- 檔案儲存：雲端物件儲存；本機開發使用相容儲存或檔案目錄
- AI：後端呼叫 DeepSeek API
- 反向代理與 HTTPS：Nginx 或雲端負載入口
- 部署：Docker Compose，保持華為雲與阿里雲之間可移植

第一版搜尋直接使用 PostgreSQL 的標準化欄位、標籤、別名與模糊比對。資料量尚小，不增加獨立搜尋服務。若日後資料量或中文語意搜尋需求明顯增加，再加入專用搜尋引擎；此擴充不改變頁面流程。

### 7.2 元件責任

- Web UI：頁面呈現、PWA、程式碼編輯、暫存草稿及離線快取。
- Server API：驗證、內容 CRUD、搜尋、匯入、備份、AI 請求及檔案授權。
- Importer：解析舊 HTML、項目檔案與 PDF，產生匯入預覽，不直接發布。
- AI Gateway：組合出題與評分提示詞、驗證結構化回應、限制重試及隱藏 API Key。
- Database：保存結構化內容、關聯、草稿、答題紀錄及狀態。
- Object Storage：保存 PDF、圖片、影片及其他附件。

### 7.3 登入與安全

- 系統只建立一個管理者帳號，不提供註冊頁。
- 密碼只保存強雜湊，不保存明文。
- 登入使用 Secure、HttpOnly、SameSite Cookie。
- 所有業務頁面及 API 均要求登入。
- DeepSeek API Key 只存在伺服器環境變數，不下發到瀏覽器。
- 檔案上傳限制允許的類型及大小，檔名在儲存前正規化。
- AI 請求設定頻率與每日用量限制，避免重複點擊造成額外費用。

### 7.4 PWA 與離線行為

網站可加入手機主畫面。離線時可閱讀已快取的最近知識點、項目及 PDF 頁面；程式碼草稿先保存於裝置。登入同步、AI 出題、AI 評分、搜尋未快取內容及正式發布需要網路。

## 8. AI 資料流與規則

```text
網站內容／PDF索引／開放 Android 知識
→ 後端建立題目提示詞
→ DeepSeek 回傳結構化題目
→ 後端驗證必要欄位
→ 前端顯示題目
→ 使用者提交答案
→ 後端建立逐項評分提示詞
→ DeepSeek 回傳結構化評估
→ 後端驗證並保存
→ 前端顯示結果及待學習動作
```

DeepSeek 可自由生成網站以外的 WorldSkills 風格新題，但每題必須提供可判斷的功能要求、限制及參考答案。評分提示詞要求模型優先考慮比賽完成速度、指出最小修改，並區分「功能錯誤」與「可選改善」。

所有 AI 產生的正式知識內容都必須經使用者確認。AI 回傳缺欄位、格式錯誤或自相矛盾時不建立正式記錄，只保留可重試的失敗狀態。

## 9. 錯誤處理

- DeepSeek 無回應：立即保存答案並提供「稍後重新評分」。
- 題目生成失敗：自動重試一次，仍失敗則返回題型選擇頁並顯示原因。
- 搜尋無結果：顯示 AI 補充按鈕，不自動呼叫 API。
- PDF 解析不完整：保留原檔並標示失敗頁面，允許直接閱讀與重新索引。
- 匯入分類不明：保存至需要整理，不直接發布。
- 影片或附件上傳失敗：保留表單草稿並允許單獨重試。
- 網路中斷：保留本地程式碼與表單草稿，恢復後由使用者確認提交。
- 登入逾時：重新登入後返回原頁，未提交草稿不清除。
- 重複待學習內容：提示合併或分開保存，不自動刪除既有資料。

## 10. 測試與驗收

### 10.1 核心流程驗收

- 搜尋可同時返回知識點、程式碼、項目及 PDF，分類篩選和排序正確。
- 項目詳情可閱讀全部內容，沒有影片時不出現空區塊。
- 程式碼檔案樹、語法高亮、複製、搜尋及練習副本均可使用。
- 三種抽題模式可產生題目、提交答案並顯示結構化評估。
- 點擊我不會、重要錯誤、新知識及 AI 補充均能建立待學習內容。
- 待學習可再次作答、編輯、轉為知識點及刪除。
- 現有 HTML、項目及 PDF 可預覽匯入，未確認前不改動原始檔案。

### 10.2 安全與可靠性驗收

- 未登入的頁面及 API 請求均被拒絕。
- DeepSeek API Key 不出現在前端 bundle、HTML 或 API 回應中。
- 密碼、Session、上傳及 AI 用量限制有自動測試。
- AI 回傳錯誤格式不會建立損壞記錄。
- 網路或 API 中斷不會遺失已輸入的答案及草稿。
- 備份可匯出，並能在乾淨測試資料庫中還原核心內容。

### 10.3 裝置與可用性驗收

- 手機底部導覽固定為首頁、搜尋、抽題、項目。
- 桌面導覽、手機導覽和瀏覽器返回行為一致。
- 中文、英文、API 名稱及程式碼符號可搜尋。
- PWA 可加入手機主畫面，已快取內容在離線模式可閱讀。
- 程式碼編輯器在手機直向畫面可輸入、水平捲動、保存草稿及提交。

## 11. 視覺方向

最終 UI 採深色科技感，但資訊層級和可讀性優先：

- 深色背景配霓虹青、紫或洋紅點綴
- 有節制的漸層、幾何線框與粒子動畫
- 標題使用具特色的科技字體，正文及程式碼使用高可讀字體
- 動畫不阻礙搜尋、閱讀和手機輸入，並尊重 reduced-motion 設定
- 程式碼、PDF 及長文區域維持足夠對比，不使用過量發光效果

視覺實作必須建立在本規格已確認的導覽與流程之上，不改變核心資訊架構。

## 12. 分期與工作樹邊界

詳細執行順序將在本規格批准後由 implementation plan 定義。為支援多個 Git 工作樹，模組邊界預先定義如下：

1. Foundation：Next.js、資料庫、登入、設計 token、測試及 Docker 基礎。
2. Content：知識點、項目、程式碼、PDF、媒體及後台 CRUD。
3. Search and Import：全站搜尋、舊 HTML／資料夾／PDF 匯入及備份。
4. AI Training：DeepSeek Gateway、抽題、作答、評分、待學習及答題紀錄。
5. PWA and Deployment：離線快取、物件儲存、Nginx、雲端部署與運維文件。

Foundation 必須先完成並成為其他工作樹共同基線。Content 的穩定資料模型與 API 契約完成後，Search and Import 與 AI Training 才能安全並行。PWA and Deployment 可提前準備容器與環境範本，但最終整合在核心功能通過驗收後進行。

不同工作樹不得同時任意修改共享 schema、全域導覽、環境變數契約或共用型別；這些變更必須先在 Foundation／整合分支協調，以降低合併衝突。

## 13. 已確認決策

- 只有一位使用者，整站登入後才可存取。
- 以手機零碎時間抽題及比賽完成速度為優先。
- AI 可生成網站以外的新題。
- AI 不執行或編譯提交程式碼。
- 不加入掌握度、間隔重複、指定主題或指定時間。
- 內容管理同時支援現有檔案匯入及網站後台新增。
- 待學習可自動建立，但轉為正式知識點需使用者確認。
- 部署採可移植容器架構，可落在華為雲或阿里雲。
- 導覽採桌面側欄與手機底部四入口的備賽儀表板。
